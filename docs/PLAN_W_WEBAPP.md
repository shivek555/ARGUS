# Plan: Phase W — web app for the class presentation (R3/R4 APIs, explanations, approvals, containment, demo mode)

**Status:** draft for review (ADR-0014 proposed). No code yet.
**Gate:** G7, "demo runs reliably from a clean checkout" (brief §8).
**Cost:** $0. Runs on the laptop with what is already installed (Python 3.11.9, Node, the locked pip/npm packages). No model downloads, no API keys, no network at demo time.

---

## 1. What changes and why

The v0 app (ADR-0002) shows the failed PoC: 10 scenarios, the old IsolationForest, a mock intent judge, and "TODO" for the hybrid, containment and approvals. All of those now exist. Phase W makes the app a window onto the **real research system**: AgentEscapeBench, the frozen R1b ML detector, the R2-L LLM verdicts (replayed), the frozen R3 risk engine with per-signal explanations, the containment session, the human approval queue, forensic snapshots, and the R4 result tables.

Rules carried over from ADR-0002:
- The app **computes no new research numbers**. Results come from committed files generated by `reproduce`. Live sessions use the same frozen code paths as the evaluation.
- Every number is labelled with where it comes from: *dev out-of-fold*, *dev in-sample (frozen model on its own training data)*, *exploratory*, or *test v2: not yet run*.
- Brief §186 wording: no "secure", "zero-day" or "prevents all attacks".

## 2. Engines and data in the app (honest about what each session uses)

| Session type | Signals | Risk engine | Why |
|---|---|---|---|
| **Bench trajectory** (dev v1 attacks, dev-v2 benign with LLM verdicts) | Precomputed exactly as R3: frozen ML, LLM **replayed** from the committed qwen2.5:3b cache | **Primary** frozen model + levels (ADR-0012) | Same inputs as the dev report. The drill-down labels them "in-sample: the model was fitted on this data" and links the out-of-fold numbers. |
| **Custom objective / hand-typed calls** | Live: policy v2/v3, frozen ML (fitted at startup, deterministic), context signals; **no LLM** (no cached verdict exists, and there is no Ollama on this PC) | Frozen **no-LLM ablation** (`configs/risk/r4/ablation-no-llm`) | The primary model never saw missing LLM verdicts on risky calls, so it would be out of distribution. This is the same choice as the v1-test exploratory run. |

Test v2 is never loaded. `argus/api/` stays inside `tests/test_blindness.py`. After the single R4-f run, its committed result tables appear on the Results page and nothing else changes.

## 3. API (FastAPI, same security model as v0)

| Method | Path | What |
|---|---|---|
| GET | `/api/meta` | Frozen artefacts with hashes (ML config, LLM model + prompt, risk model, levels, R4 manifest), signal names and labels, level → decision table, policy rules, tool catalogue |
| GET | `/api/bench?split=&family=&variant=` | Trajectory headers (dev attacks, dev-v2 benign subset, v1 test exploratory) |
| GET | `/api/bench/{id}` | Per step: call, ground-truth label, policy rule, ML anomaly, LLM verdict + reason, risk points, level, decision, **contributions (baseline + per-signal points = score)**, recommended response; per-method first-flag steps |
| POST | `/api/sessions` | `{objective_text, allowed_scopes}` or `{trajectory_id}`; the response states the engine used (§2) |
| POST | `/api/sessions/{id}/calls` | One call through `ContainedSession` (enforce mode): `executed` / `held` (+ approval id) / `blocked` (+ reason), with the full `RiskDecision` |
| POST | `/api/sessions/{id}/script/next` | Next scripted call of a bench trajectory |
| GET | `/api/approvals` | Pending items (with time left) and history |
| POST | `/api/approvals/{id}` | `{approve, reviewer}`. Reserved actor names are rejected (no self-approval). Expiry auto-denies. |
| GET | `/api/forensics`, `/api/forensics/{session_id}` | Snapshot list and content (already redacted) |
| POST | `/api/forensics/{session_id}/verify` | Recomputes sha256 server-side: OK or tampered |
| GET | `/api/results/{name}` | Whitelisted committed JSON from `docs/results/` (R4 dev, R3 dev, R1b, R2-L, latency) |
| GET | `/api/results/figures/{name}.svg` | Whitelisted SVG figures |

**Retired:** `POST /api/experiments/poc/run` (re-running evaluations from a web page is not needed and widens the attack surface). The PoC scenario and experiment pages move to a read-only **Archive** (the story of why G3 failed is part of the talk).

**`reproduce` additions (W-b):** it also writes the app's inputs as rounded JSON (`docs/results/r4_dev.json`, `r3_dev.json`, `r1b_dev_selection.json`, `r2l_runs.json`). These are checked byte-for-byte in CI like the tables, so a clean checkout has everything the app shows. `eval/results/` stays gitignored.

**Security (all tested):** binds 127.0.0.1; no CORS; CSP / nosniff / frame-deny / no-referrer; bounded inputs (as v0); session, snapshot and approval ids must be 32-hex (no path traversal); results and figure names whitelisted; snapshots under `eval/results/forensics/` (gitignored), write-once; responses carry only redacted args/results, and canary secrets never appear (existing test extended); objective immutable after session creation. The approval "reviewer" is a self-declared name, not authentication. This is a local demo tool, and the page says so.

## 4. Pages (React + TypeScript; still no router library, no chart library)

| Page | Content |
|---|---|
| **Overview** | Research question and RQ1–RQ6; the phase/gate board (G1–G7 status with links to evidence); headline dev numbers with their labels; what is frozen (with hashes); what is not done (test v2, R5) |
| **Benchmark** | Filterable table of trajectories (family, variant, benign intent); for each one, which methods flag it and at which step vs the first unsafe step |
| **Trajectory** | Step timeline: policy rule, ML anomaly, LLM verdict + reason, risk level band chart; click a step → **explanation panel** (waterfall: baseline + signal contributions = risk points, thresholds, decision, recommended response) |
| **Live session** | Start from a bench trajectory or a custom objective; send or step calls; each result shows its decision and explanation; HIGH → "held, waiting for a human" with a link to Approvals; CRITICAL → quarantine banner, tools revoked, snapshot link |
| **Approvals** | Pending queue with a countdown, approve/deny with reviewer name, decision history; shows that an approved call still goes through the policy gateway |
| **Forensics** | Snapshots: trigger decision, events, decisions, files written, egress (redacted); "Verify sha256" button |
| **Results** | R4 dev tables (methods, CIs, McNemar/Holm, containment, LOFO/G6, seeds), the 3 SVG figures, R1b selection, R2-L runs, latency (laptop + CI), provenance (command, frozen hashes, CI status). A test-v2 section shows "not yet run" until R4-f. |
| **Archive** | v0 PoC scenarios and the failed G3/G4 runs, read-only |

Presenter features: large-text toggle, light/dark (both checked), keyboard navigation (← →) in demo mode, and no layout shift when values update.

## 5. Demo mode (`#/demo`) — a guided, deterministic 8–10 minute tour

Each card drives the real API (no recorded responses). A "Reset demo" button clears sessions, approvals and demo snapshots. Proposed beats (actual trajectories chosen in W-d from dev v1 / dev v2, never test v2):

1. **Benign task, allowed.** Low risk, explanation shows why.
2. **Policy-visible attack.** The policy rule fires, CRITICAL, quarantine, forensic snapshot, verify sha256.
3. **Policy-compliant exfiltration the rules miss.** The hybrid raises HIGH before the harmful step; the call is held; the presenter (a human) denies it; harm never executes.
4. **Approval still obeys policy.** Approving a call to a non-allowlisted destination is still blocked.
5. **An honest false alarm.** A legitimate secrets task held for approval: the cost of the system (R3-c workload 27/100 fails its target).
6. **Results.** Hybrid vs components (dev), seed variance, LLM adds ≈ nothing, latency, and what test v2 will decide.

`docs/DEMO_SCRIPT.md`: speaker notes per beat, timings, likely questions with honest answers, and a fallback if the laptop fails (the committed `docs/results/` tables and figures render on GitHub without the app).

## 6. G7 — "demo runs reliably from a clean checkout" (pre-registered)

**G7 PASS iff** a CI job on a fresh `ubuntu-24.04` checkout does all of the following, and the same sequence passes on the laptop (Windows) at the W-f rehearsal:
1. Install locked deps (pip + `npm ci`) and build the dashboard.
2. Start `python -m argus.api` on 127.0.0.1.
3. Over real HTTP, run every demo beat and assert its expected outcome (allowed / CRITICAL + snapshot verifies / held → denied → harm absent / approved-but-blocked / benign held).
4. Load every page route and every results file the UI requests (no 404/500).
5. Stop cleanly, all within a 10-minute CI budget.

## 8. Risks

- **Startup time:** fitting the frozen ML and its threshold at startup takes seconds. The UI shows a "warming up" state; it is measured in W-a.
- **Demo drift:** a demo beat's outcome depends on frozen models. The G7 test pins every expected outcome, so drift fails CI, not the class.
- **Over-trusting the UI:** dev in-sample decisions look better than out-of-fold numbers. Every per-trajectory view carries the label and links the out-of-fold table.
- **Scope creep:** no auth, no multi-user, no cloud deploy, no live LLM in the app.
